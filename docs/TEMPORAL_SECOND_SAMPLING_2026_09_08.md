# 时序模型二次采样：实现与首轮实测

## 结论与产品选择

服务保留两条二次采样路线，并把用途说清楚：

- `temporal` 是新版UI默认值。它从已经完成的视频出发，使用 FlashVSR v1.1 Tiny Long
  做一次单步时序视频扩散，目标是同时恢复整幅画面的纹理、远景结构和人物面部，并在
  相邻帧之间保持稳定。
- `h3` 是原有的H3生成式二采。它从保留的干净AV latent出发，继续使用H3 Base、
  原提示词和参考条件重新生成高分辨率细节，适合愿意用更长时间换取更强生成式重建的
  任务。

这不是把H3二采删除后换成逐帧锐化。`temporal`仍是带长时序上下文的视频到视频扩散
推理；它只把负责二采的模型换成了针对视频恢复蒸馏的一步DiT。顺序执行“先H3二采、
再时序恢复”在本轮实测中既更慢，也会把H3已经重建错误的小脸继续传给后级，因此没有
设为产品路线。

## 为什么处理当前缺陷

低步数H3二采必须从有噪latent重新求解整段画面。远处物体和十几至几十像素的小脸在
源视频里约束很弱；采样步不足时，模型容易在每帧给出不同的高频猜测，于是产生背景
发糊、货架边缘游移和小脸结构抖动。继续减少H3步数可以加快任务，却会放大这个矛盾。

时序路线直接把已生成视频作为强条件，保留其构图和动作，再用跨帧特征恢复纹理。单步
蒸馏减少了重复求解完整H3生成轨迹的成本。它并不能恢复源视频从未包含的真实身份细节，
但会避免把每一帧当成彼此无关的静态图像。

## 对照设计

- 源任务：`391db2fe-ac2d-4a9b-8c1d-417d430da8ea`
- 输入：864×480，124帧，24fps，5.1667秒
- 场景：固定广角超市画面，四个人分布在近、中、远距离，背景包含密集货架和直线边缘
- 目标：1344×768，124帧，保留原音频
- 当前H3对照：2个真实二采步，任务
  `ecb26b3f-f03e-44f9-a54b-b71a4ea46679`
- 新时序路线：1个时序扩散步，正式API任务
  `3281e7ba-c41b-4a56-b41f-b6e16e5686dd`

两条路线来自同一个源任务，输出尺寸、帧数、帧率和音频保持一致。最终视觉优劣由Human
观看同步视频判断，不用单帧代理指标替代动态判断。

## 端到端结果

| 路线 | 端到端时间 | 相对当前H3二采 | 峰值CUDA allocated / reserved |
|---|---:|---:|---:|
| 当前H3二采，2步 | 38.760秒 | 1.00× | 未在旧任务中记录 |
| H3二采，1步 | 27.769秒 | 1.40× | 未在旧任务中记录 |
| 新时序模型二采，1步 | 19.604秒 | **1.98×** | 11476.5 / 12116.0 MiB |
| H3 1步后再做时序恢复 | 44.714秒 | 0.87× | 两个任务顺序执行 |

新路线相对当前H3两步二采减少19.156秒，即49.42%。19.604秒由公开任务生命周期计时，
不是只截取CUDA kernel：

| 阶段 | 时间 |
|---|---:|
| 解码与预处理 | 2.347秒 |
| GPU准备 | 1.965秒 |
| 单步时序DiT推理 | 11.187秒 |
| 后处理、编码与音频复用 | 3.490秒 |
| Worker任务 | 19.061秒 |
| HTTP任务端到端 | 19.604秒 |

首次服务启动会把约6.00GiB的时序模型权重预载入CPU内存，本机模型装载10.838秒、
守护进程就绪12.778秒；这部分不计入每次任务。执行时模型按需进入GPU，任务结束后释放
GPU，以免长期占用H3生成显存。

## API与兼容性

新版调用：

```json
{"method": "temporal", "resolution": "1080p"}
```

旧客户端省略`method`时继续走`h3`，所以原有集成不会改变行为。时序路线只要求任务的
成片仍存在；H3路线仍要求保留干净AV latent。UI会根据每张任务卡的实际文件状态分别
启用两种方法。

FlashVSR源码固定在
`OpenImagingLab/FlashVSR@b527c6f285fb30df530f5febc8b45764a789c961`，权重固定在
`JunhaoZhuang/FlashVSR-v1.1@63a588528f1e25de6c3ebd5fdade4481dce2bbf1`。源码、
模型均声明Apache-2.0；文件大小和SHA-256记录在`models/manifest.json`。

## 当前证据边界

1. 1.98×是这一个5.1667秒、480P到1344×768样例在RTX 4090上的实测，不外推成所有
   时长、分辨率和运动类型的固定加速倍数。
2. 时序路线需要额外约6.00GiB磁盘权重和独立Python/Torch运行环境，但任务期间不需要
   同时加载H3权重到GPU。
3. 极小人脸在源片中若已经缺失五官信息，模型只能生成合理结构，不能证明恢复了真实
   身份。涉及身份忠实度时仍应使用参考图或专门的人脸修复路线复核。
