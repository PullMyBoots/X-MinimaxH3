# H3复杂台词与大动作统一验收协议

日期：2026-08-12  
状态：Human批准的后续统一测试规则；阈值需由基线分布校准，禁止拍脑袋设定

## 统一测试任务

后续加速候选不再以无台词、慢运动或单一大场面作为主要验收样例。默认使用
`benchmarks/acceptance/complex_dialogue_motion_v1.json`：864x480、243帧、24 FPS、
10.125秒、固定seed 82301。任务包含两个稳定角色、三句普通话、三个明确时间窗、
跨画面的跑动/关门/登阶举火把和三个指定环境音事件。

基线与候选必须固定模型路线、prompt、seed、画布、帧数、采样器、质量计划和首尾帧
条件；一次实验只改变待审加速机制。720p/15秒等压力档可以复用同一叙事结构并按
时长扩展时间窗，但不得退回简单无台词提示词作为质量结论的唯一证据。

## 验收顺序

1. 检查任务成功、OOM、媒体结构、视频/音频时长、分辨率和帧数。
2. 固定使用部署环境中已验证的 `/path/to/whisperX` WhisperX
   管线：`large-v3`、中文提示、GPU FP16、VAD和中文强制对齐，并保留
   segment/word时间戳。报告必须记录WhisperX版本、源码commit/路径、底层
   Faster-Whisper版本、VAD、对齐模型和解码参数。不得用直接调用
   Faster-Whisper CPU/INT8的结果冒充该验收管线。
3. WhisperX只提供台词内容、顺序和时间指令遵循证据。VAD漏检、ASR幻听或错字
   不得直接判定模型漏说/多说台词；与Human听感冲突时标记为ASR不确定并由Human
   连续播放裁决。WhisperX不能判断倒带、爆音、刺耳噪声、音色、说话人身份、口型
   或表演是否自然，这些由音频检查、对应时间戳关键帧和Human成片复核。
4. 每条视频抽取4到8帧，优先使用manifest指定的动作中点和转场边界，而不是只做
   均匀抽帧。检查彩斑、闪烁、散光重影、VAE接缝、人物身份、结构崩坏、大动作连续
   性和无关物体。灾难性视觉失败立即隔离。
5. 视觉与Whisper证据之后记录热态端到端时间、冷启动、逐阶段时间、峰值显存、GPU
   利用率和OOM。正式速度使用同一常驻进程的重复热态统计；单次运行只算候选证据。
6. SSIM、PSNR、音频波形/embedding差异只作轨迹漂移参考，不设硬阈值，不得单独
   决定晋级或淘汰。
7. Human最终审核说话人、口型、动作幅度、时间段执行、额外台词和整体音画质量。

## Whisper指令遵循报告

至少输出：

- 三句期望台词是否被识别及归一化文本；
- 句级/字级时间戳和期望窗口；
- 台词顺序是否正确；
- 字符错误率或字符匹配率；
- 每句时间窗重叠率、起止偏差；
- 额外语音片段、持续时间和文本；
- WhisperX模型、源码commit/路径、版本、底层Faster-Whisper版本、语言、VAD、
  对齐模型、解码参数和原始转写JSON；
- ASR与Human听感是否冲突，以及冲突后的Human裁决；
- 非语音音频伪影（倒带、爆音、噪声、刺耳音色）必须单独记录，不折算为CER。

在完成原始权重、LoRA稠密和至少三个seed的基线分布前，不设置任意固定通过分数。
加速候选首先比较是否丢失基线能够正确生成的台词、是否增加额外语音、是否扩大时间
偏差；阈值在基线分布形成后再由Human/Main确认。

## 证据优先级

```text
媒体有效性
  -> Whisper台词/顺序/时间戳
  -> 4~8帧视觉正常与动作检查
  -> Human音画终审
  -> 性能与显存
  -> SSIM和音频差异（仅参考）
```

速度或低SSIM都不能覆盖台词缺失、时间指令失败、灾难性画面异常或Human判定不可用。
