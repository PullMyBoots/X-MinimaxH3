# H3 2K 二采：原生时间窗口执行器

## 已确认的发布边界

- 24GB INT8 首遍生成最高 1080p×15 秒。
- 2K 只作为已完成低分辨率任务的 H3 二次采样目标。
- 旧 2K×15 秒证据只完成一个 Actual DiT 门；2026-08-27 的真实多步任务持续产生
  13–16.5GB/s PCIe 换页、110–148W 功耗并停留在 DiT 载入阶段，因此不能作为发布能力。

## 上游 Ultimate Upscale 可复用机制

上游的核心流程不是把整个 2K×15 秒 AV latent 一次塞入 H3：

```text
时间切窗（外层）
  -> 每窗 learned 3D latent upscale
  -> conditioning 时间重锚
  -> 上一窗边界帧锚定
  -> 整窗采样；若仍放不下，再空间切块
  -> 空间重叠冻结/淡化
  -> 时间重叠交叉淡化
  -> 原始音频 latent 保留
  -> 完整 latent 只解码一次
```

默认时间窗为 136 像素帧、重叠 17 帧。362 帧会形成约三个窗口，重复工作约 13%，
但 Attention 的时间长度平方项显著下降。空间 512×512 tile 不是默认必须照搬的质量设置，
而是单个时间窗仍超出显存时的第二级容量兜底。

对H3 362帧的精确时间token网格，136/17产生三段 `0:40`、`35:75`、`70:107`。
计入约1800个条件/音频前缀token后，1080p和2K的纯Attention cell量分别降到整段的
约41.1%和40.6%；线性MLP/投影工作因重叠增加约10–11%。这说明时间窗不只是省显存，
对长视频也是一条实质的Attention加速路径。

## 24GB 的速度优先路由

1. 720p/短视频二采：整段全画布。
2. 1080p×15 秒：比较整段实测成本与 136/17 时间窗；发布前由同源 Human A/B 决定。
3. 2K 长视频：默认 136/17 时间窗，保持完整空间画布。
4. 单个完整空间时间窗仍超预算：才启用空间 tile；从最大可行 tile 开始，而不是直接 512。
5. 所有窗口均使用真实 DiT 步；Forecast 关闭；加速力度只投影到逐层 Attention。

这个次序避免两种浪费：整段上下文的 PCIe 换页，以及不必要的几十个小空间 tile。

## 必须保持的数值与语义不变量

- 时间边界对齐 H3 五 token 相位。
- Video 与 Audio 使用不同时间坐标切片，不能共用 video token 下标。
- 重叠窗口使用同一全局噪声场的坐标切片，避免同一帧得到两份无关噪声。
- 每窗参考 keyframe 按全局帧区间裁切并重编号。
- 第二窗起将上一窗已采样边界作为 frame-0 条件锚。
- 音频默认直接保留源 latent，不让逐窗视频修复重新生成台词。
- 拼接在 H3 latent 中完成，最后只执行一次 Video/Audio VAE 解码。
- 每层、每个 Query chunk、每窗边界均检查取消信号。

## 原生实现状态

已完成：

- 24GB 首遍 2K 的 UI/API/Advanced 尺寸硬禁用；2K 二采仍保留。
- 相位对齐的时间窗口规划。
- 独立 Video/Audio 时间坐标切片。
- AV latent 重叠交叉淡化拼接。
- 每窗 learned 3D upscale 与真实 DiT 采样循环。
- 三窗进度映射、窗/步边界取消、原始音频完整保留。
- 拼接后单次完整 VAE 解码；发布代码固定使用已验证的精确 host-temporal
  Video-VAE 图，避免完整FP32 2K帧驻留GPU。
- 2K 单步门降级为容量证据，不再作为完整成片发布证据。

2026-08-28 真权重门使用已有480P×15秒clean latent，执行2K、1个真实二采步、
75加速、0.20重绘：

- 三个窗口为`0:40`、`35:75`、`70:107`，空间不切块，计算冗余1.0939×；
- 热后端二采端到端287.931秒；完整冷启动墙钟315.486秒，其中加载22.714秒；
- DiT窗口持续约473–482W、SM 99–100%，物理显存主要为14.7–18.6GB；
- 不再出现整段路线持续13–16.5GB/s PCIe RX与110–148W低功耗；
- 生成真实2560×1440、362帧、15.084秒、H.264/AAC MP4。

尚未照搬、需要Human质量A/B后再决定的上游机制：

- 上一窗边界frame-0 conditioning锚（当前已有17帧latent交叉淡化，但未注入
  上游0.999条件锚；Ref2VA还需保持Qwen视觉行与reference layout严格一致）。
- 必要时的空间tile noise-mask与条件裁切；24GB当前三窗均能满功率执行，因而不付

- 全局噪声坐标切片；当前各窗复用同一seed，但不是全局噪声张量的坐标裁切。
- 480P/720P源到2K的1/3/5步Human质量A/B；当前MP4只证明端到端与物理效率，
  不单独证明接缝质量或最佳重绘参数。

## 发布验收

- 2K×15 秒必须有真实 MP4，而不是单步 checkpoint。
- NVML 平均功耗、PCIe 带宽、峰值显存和端到端耗时必须记录。
- 不允许出现持续十秒以上的 10GB/s 级 PCIe 换页。
- 与上游 136/17 基线比较接缝、运动连续性、人物/物体一致性和局部清晰度。
- 与整段 1080p 二采比较；没有同质量提速时不自动扩展到 1080p。
